# Arrive Shipping — الأسئلة والقرارات

> ReadyCar بتجهز Arrive كشركة شحن تالتة جنب بوسطة وتالا، مع سويتش واحد يبدّل بينهم.
>
> جربنا البورتال والـ API بتاريخ 2026-09-13 بحساب `01006506508` (Ready Car — shipper `29206`).
> اللي اتأكدنا منه متوثّق في `Backend/docs/ARRIVE_INTEGRATION.md`، وفيه نسخة PDF مختصرة
> للإرسال في `Arrive-Integration-Questions.pdf` في جذر المشروع.
> الملف ده فيه: (أ) أسئلة لـ Arrive، (ب) فروق التشغيل اللي محتاجة قرار من ReadyCar،
> (ج) شكل السويتش في السيستم.

## أ. أسئلة لـ Arrive

### ١. بيانات الـ API — البلوكر الأول
كل استدعاء للـ API بيرجّع `401 "User Not Found"` ببيانات البورتال. الدوكيومنتيشن بيقول
`user` = "API Name" و `password` = "API Password".

- **محتاجين بيانات API لحساب Ready Car (29206).** بتتولّد إزاي؟ ومن مين؟
- بيانات الـ API مرتبطة بباسورد البورتال؟ (البورتال بيطلب تغيير الباسورد خلال يومين وإلا
  الحساب يتوقف — لو غيّرناه هل الـ API هيتأثر؟)
- فيه **بيئة تجريبية** ولا كل شحنة بالـ API حقيقية وبتتحاسب؟

### ٢. البيك أب
أول حالة لأي شحنة جديدة هي `1` "طلب بيك أب".

- **إنشاء الشحنة بالـ API بيعتبر طلب بيك أب تلقائي؟** ولا لازم نعمل "طلب" من البورتال كمان؟
- لو تلقائي: المندوب بييجي إمتى؟ فيه deadline يومي (مثلاً قبل الساعة كذا = نفس اليوم)؟
- ينفع API لطلب البيك أب (نفس فورم "اضف طلب": العدد، وسيلة النقل، الموعد)؟
- **إحنا سوق متعدد التجار**، كل أوردر ممكن يتقسم على أكتر من تاجر في أكتر من فرع.
  البيك أب بيتعمل من عنوان الحساب (لوران - الإسكندرية) بس؟ ولا ينفع من عناوين مختلفة؟

### ٣. عنوان الراسل لكل شحنة — أهم سؤال تشغيلي
في فورم البورتال فيه حقول "الراسل الفرعى" (اسم / رقم / عنوان / منطقة)، لكن **مش موجودة
في الـ API**.

- ينفع تضيفوها للـ API (`sender_name`, `sender_phone`, `sender_address`, `sender_sector`)؟
- ولا الحل إن كل فرع تاجر عندنا يتسجّل كـ "راسل" منفصل عندكم تحت حساب Ready Car؟
- ولا كل حاجة لازم تتجمع في مكان واحد ونشحن منه؟

### ٤. الفلوس
- `price` هو المبلغ اللي المندوب بيحصّله من العميل **بالظبط**؟ ولا بتزوّدوا الشحن فوقه؟
- **الأوردر المدفوع أونلاين**: نبعت `price = 0`؟ ولا فيه نوع خدمة "تسليم بدون تحصيل"؟
- **رسوم التحصيل**: صفر؟ مفيش نسبة على المبلغ؟ فيه حد أقصى للمبلغ في الشحنة؟
- **الطرد المرفوض بيكلفنا كام بالظبط؟** الحاسبة بتقول `costing_refuse` = سعر الشحن
  (70–120) و `costing_returned` = 20. يعني 70 + 20 = 90؟ ولا 70 بس؟ ولا 20 بس؟
- **الإلغاء** `costing_cancel` = سعر الشحن كامل. بيتحاسب من إمتى؟ قبل البيك أب مجاني؟
- `costing_returnedPaid` و `costing_replace` معناهم إيه؟
- الأسعار شاملة ضريبة؟
- **دورة التسوية:** بتحوّلوا المبالغ المحصّلة كل قد إيه؟ وإزاي نعرف من الـ API إن تحويل حصل؟
- الأسعار اللي في الحاسبة **ثابتة بعقد** ولا ممكن تتغير من غير إخطار؟

### ٥. الحالات والـ webhook
- الفرق بين `5` "تسليم ناجح" و `33` "تم التسليم"؟
- `105` "مرتجعات انتجريشن" و `115` "استلام انتجريشن" — دول لينا كشركاء ربط؟ معناهم إيه؟
- أنهي حالات **نهائية**؟ (نفترض `14` و `8` للمرتجع، و `5`/`33` للتسليم)
- بتحاولوا **3 مرات** (`45`/`46`/`47`) وبعدها بترجّعوا؟ في كام يوم؟
- **الـ webhook مفيش فيه وقت الحدث.** ينفع تضيفوا `date_created` زي `statusHistory`؟
  ده مهم عشان لو التحديثات وصلت بترتيب غلط منرجّعش الشحنة لحالة أقدم.
- بتعيدوا المحاولة لو السيرفر بتاعنا رد بخطأ؟ كام مرة؟
- الـ webhook بيتظبط من عندكم؟ **هنبعتلكم الرابط** — فيه سيكرت أو توقيع؟
- `getCurrentStatus` بيرجّع الاسم بس من غير `status_id` — ينفع تضيفوا الكود؟

### ٦. الطباعة والفلايرز
- فيه API بترجّع البوليصة PDF؟ لو لأ، **ينفع نرسم الملصق بنفسنا**؟ إيه الحد الأدنى اللي
  لازم يكون عليه عشان المندوب والمخزن يقبلوه؟ الباركود على الـ `waybill` ولا على الـ `qr_code`؟
- **"رقم الفلاير" / "رصيد الفلايرز"**: ده نظام أكياس مرقّمة مطبوعة مقدماً؟
  - بنطلبها منكم إزاي؟ وبتتحاسب؟
  - لو التاجر لزق فلاير رقمه `X` على الطرد وبعتنا `email = X` في الـ API، المندوب هيقبله
    من غير بوليصة مطبوعة؟ (ده نظام "Smart Label" اللي شغال معانا مع بوسطة)
  - `printLabel10EmptyWaybills` — بوالص فاضية؟ نفس الفكرة؟

### ٧. الإلغاء والتعديل
- مفيش API للإلغاء. لو العميل لغى بعد ما الشحنة اتعملت، نعمل إيه؟ "طلب" من البورتال؟
- تعديل العنوان أو الموبايل بعد الإنشاء؟

### ٨. منع التكرار
- لو النت قطع وأعدنا إرسال نفس الشحنة بنفس `order_id`، **بتعملوا شحنتين ولا بترفضوا التانية؟**
  (بوسطة عندها حقل بيمنع ده وأنقذنا كذا مرة)

### ٩. المناطق
- 9 مناطق اسمها "غير مخدومة" (شرم الشيخ، دهب، العريش، رفح، الشيخ زويد، الخارجة، الجلاتمة،
  **العاصمة الإدارية**) — فعلاً مش بتوصلوها؟ ولا بسعر 130؟
- `keyword` بدل `sector_id`: لو المنطقة مش متطابقة بيحصل إيه؟ بترفضوا ولا بتختاروا أقرب حاجة؟
- قايمة المناطق بتتغير كل قد إيه؟ (هنخزنها عندنا)
- المجموعة "فري" (سعر 1 جنيه) دي إيه؟

### ١٠. الوزن والحجم
- الوزن المسموح 2 كجم وفوقه 5 جنيه/كجم — ده لكل الشحنات؟ فيه حد أقصى؟
- فيه اعتبار للحجم (قطع غيار كبيرة زي مرايات/صدامات)؟ حقل `size` في البورتال بيعمل إيه؟

### ١١. متفرقات
- `addBulkShipments`: شكل الريكوست في الـ PDF مش JSON صحيح — ممكن مثال شغال؟
- `client_id` ("كود العميل") لازم يتسجّل عندكم الأول ولا أي رقم؟
- rate limit 50/دقيقة — ده على كل الـ actions مجتمعة؟

### ١٢. إفصاح أمني (نبلّغهم كحسن نية)
- `shippings.php?action=GetAllCouriers` بحساب تاجر عادي بيرجّع **كل موظفي ومناديب الفليت**
  بأسمائهم وأرقامهم الداخلية و`marketing_code`. يُفضّل تقييد الصلاحية.

### ملخص: أقل حاجة محتاجينها عشان نبدأ التنفيذ
1. **بيانات الـ API** (user + password)
2. **البيك أب تلقائي مع الشحنة ولا لأ**
3. **عنوان الراسل لكل شحنة** — ينفع في الـ API ولا لأ
4. **الطرد المرفوض والإلغاء بيكلفوا كام**
5. **`price` = المبلغ النهائي؟ والأوردر المدفوع أونلاين بيتبعت إزاي؟**
6. **ظبط الـ webhook** على رابطنا

## ج. شكل السويتش في السيستم (ملخص تصميمي)

مبني على خريطة نقاط الربط ببوسطة في الكود (اتعملت 2026-09-13) والقرار اللي اتاخد مع تالا:
**سويتش عام واحد، والشحنات الجارية تفضل مع شركتها.**

### ١. الإعداد
- `ShippingSettings.courier_provider: "bosta" | "tala" | "arrive"` — نفس نمط
  `services/paymentGateway.js` (الـ provider بيتخزن **على السجل** وقت الإنشاء، مش بيتقرا
  من الإعدادات وقت الـ webhook أو الـ sweep).
- شاشة الأدمن: `admin/dashboard/shipping/settings` — قسم "شركة الشحن" فوق قسم البيك أب.
- بيانات كل شركة في الـ env: `ARRIVE_API_USER`, `ARRIVE_API_PASSWORD`, `ARRIVE_WEBHOOK_SECRET`.

### ٢. طبقة موحّدة (adapter) لكل شركة
واجهة واحدة `services/couriers/<provider>.js` بتنفّذ:

```
createShipment(parcel)      → { provider_id, tracking_number, label_ref }
cancelShipment(shipment)    → أو ترمي NOT_SUPPORTED
track(tracking_numbers[])   → [{ tracking_number, raw_status, order_status, event_at }]
bookPickup(...)             → أو NOT_SUPPORTED
priceQuote(parcel)          → من ملف تعريفة أو API
printLabel(shipment)        → PDF من API، أو null (نرسمها إحنا)
capabilities                → { pickupApi, cancelApi, labelApi, priceApi, perParcelSender, smartLabel }
```

الـ `capabilities` هي اللي بتخلّي الواجهات تخفي زرار "احجز مندوب" أو "اطبع البوليصة"
لما الشركة الشغالة مش بتدعمه — بدل ما نعمل `if (provider === ...)` في كل مكان.

### ٣. الحقول على المستندات (أكبر شغل)
الحقول الحالية باسم بوسطة: `bosta_delivery_id`, `bosta_tracking_number`, `bosta_status`,
`bosta_cost`, `pickup_id → BostaPickup`, `sellers.locations[].bosta_location_id`,
`returnRequests.return_shipment.bosta_*`. **وبتظهر بنفس الاسم في الـ API العام والفرونت.**

المقترح: نضيف `provider` + `tracking_number` + `provider_shipment_id` + `provider_status`
على `shipments[]` و `return_shipment`، ونسيب حقول `bosta_*` زي ما هي (بتتملي لبوسطة بس)
لحد ما الفرونت يتنقل — بدل migration كبيرة مرة واحدة.

### ٤. الحالات
`bostaStatusMap.js` بيبقى `couriers/bosta/statusMap.js`، وكل شركة ليها جدول:
كود الشركة → حالتنا الداخلية → `applyStatusToOrder` **المشترك** (نفس اللي موجود).

### ٥. الـ webhook والـ sweep
- مسار لكل شركة: `/api/webhooks/arrive/:secret` (Arrive بيبعت `waybill` + `status_id`).
- الـ sweep بيجمّع الشحنات حسب `provider` وبيندّه على `track()` بتاع كل شركة —
  لـ Arrive بـ batches من 50 مع احترام 50 ريكوست/دقيقة.

### ٦. المناطق
جدول ربط لكل شركة على منطقة ReadyCar: `{ bosta_sector, tala_zone_id + tala_subzone_id,
arrive_sector_id }`. الـ seeder بتاع Arrive بيقرا `docs/arrive-sectors.json`.

### ٧. التكلفة
`courierCostService` بياخد `provider` ويقرا التعريفة المناسبة (`bostaTariff.js` أو
`arrive-tariff.json`) — نفس قاعدة **التجميد وقت الإرسال**.
