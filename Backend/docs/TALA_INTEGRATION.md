## ٤. الفلوس — `priceTypeCode` هو القرار المهم

| | `price` معناه | العميل يدفع | ملاحظة |
|---|---|---|---|
| **`EXCLD`** | ثمن البضاعة | `price + الشحن` | تالا بتزوّد الشحن فوق |
| **`INCLD`** | **الإجمالي النهائي** | `price` بالظبط | تالا بتخصم الشحن منه |

**لـ ReadyCar الصح هو `INCLD`** مع `price = subOrder.cod_amount` — لأن إجمالي العميل
متثبّت عندنا وقت الأوردر وبيشمل نصيبه من الشحن. لو استخدمنا `EXCLD` تالا هتزوّد 75 جنيه
فوق المبلغ والعميل هيتحاسب على حاجة غير اللي وافق عليها.

مثال متحقق منه: `price=500` + `INCLD` → `amount=425`, `delivery=75`, `total=500`.

### وسيلة الدفع
| الكود | المعنى | نستخدمه لـ |
|---|---|---|
| `COLC` | واجبة التحصيل | أوردر COD |
| `CASH` | مسددة نقدا | أوردر مدفوع أونلاين |

### التسعير الحي — `calculateShipmentFees`
شغال، وبيستخدم قائمة أسعارنا أوتوماتيك. **متبعتش `customerId`** (ممنوع).
**لازم تبعت `customerTypeCode: MERCHANT` و `senderZoneId`** — الاتنين مكتوبين اختياريين
في الـ schema بس الـ validation بترفض من غيرهم.

أسعارنا الفعلية (1 كجم):

| المسار | الشحن | الإرجاع |
|---|---|---|
| داخل القاهرة / الاسكندرية | 75 | 75 |
| اسكندرية → القاهرة | 75 | 75 |
| → المنصورة | 85 | 85 |
| → اسوان | 110 | 110 |
| → الغردقة | 140 | 140 |

- **الوزن الزائد:** 5 كجم → +14 · 15 كجم → +35
- **رسوم التحصيل = صفر** حتى على 50,000 جنيه (بوسطة بتاخد 1% فوق حد معين) ✅
- `tax` و `post` بيرجعوا `null`
- `dimFactor = 5000` (الوزن الحجمي = ط×ع×ا ÷ 5000)

### سياسة المرتجعات (رد دعم تالا، 2026-09-13)

| الحالة | مصاريف |
|---|---|
| العميل **رفض** الاستلام | ✅ بيتحسب |
| العميل **رفض أو اتهرب بعد التنسيق ووصول المندوب** | ✅ بيتحسب |
| الشحنة **اتلغت قبل ما المندوب يروح للعميل** | ❌ صفر |
| طلب **المرتجعات لوحدها من غير بيك اب** | **50 جنيه** |

- **مصاريف المرتجع مش على كل طرد راجع** — بس لما العميل يرفض أو يتهرب بعد ما المندوب يوصله.
  أسباب الإلغاء اللي بتطابق الحالتين دول موجودة في `listCancellationReasonsDropdown`:
  `6` العميل رفض الاستلام · `7` العميل بيتهرب من الاستلام · `33` تهرب بعد الوصول.
  يعني نقدر نعرف من `cancellationReasonId` في الـ callback إذا كان الطرد عليه مصاريف ولا لأ.
- **الإلغاء مجاني لحد ما المندوب يطلع للعميل** — أوسع من بوسطة، اللي بتقفل الإلغاء أول ما يتحجز مندوب.
- **الـ 50 جنيه:** لو طلبنا ترجيع المرتجعات للتاجر في مشوار لوحده. لو جت مع زيارة بيك اب، مفيش رسوم.

✅ **المبلغ اتحسم:** المصاريف دي **مش إضافية فوق الشحن** — هي بس "الشحن اللي العميل
مدفعهوش". يعني الطرد المرفوض بيكلفنا **75 جنيه، مش 150**. وده منطقي مع `INCLD`: في التوصيل
الناجح تالا بتخصم الـ 75 من المبلغ المحصّل، وفي الرفض مفيش تحصيل فبندفعها إحنا.

**يعني تكلفة طرد تالا علينا:**

| اللي حصل للطرد | التكلفة |
|---|---|
| اتسلّم | الشحن (75) |
| رفض / تهرب بعد وصول المندوب | الشحن (75) — نفس الرقم، مفيش إرجاع فوقه |
| رجع لأي سبب تاني | صفر |
| اتلغى قبل ما المندوب يطلع للعميل | صفر |
| مرتجعات من غير بيك اب | + 50 |

**مقارنة ببوسطة** (القاهرة، مقاس عادي): طرد مرفوض = شحن 97 + إرجاع 87 = 184 قبل الضريبة
(~210 بالضريبة) — مقابل **75** في تالا.

**أثره على الكود:** في بوسطة `courier_cost.rto` بيتضاف فوق `send` لما الطرد يرجع. في تالا
`rto` يفضل **صفر دايماً**؛ اللي بيتغير هو `send` نفسه — يتصفّر لو الشحنة اتلغت قبل ما
المندوب يطلع أو رجعت لسبب غير الرفض. الخسارة الحقيقية في الرفض إن نصيب العميل من الشحن
(`charged`) متحصلش، مش إن فيه تكلفة زيادة.

⚠️ حقل `return` في `calculateShipmentFees` مش هو اللي بيتخصم فعلاً (في إسكندرية طلع 85
والشحن 75). نتأكد من أول فاتورة حقيقية فيها طرد مرفوض.

❓ **لسه مفتوح:** الـ 50 جنيه على **كل مرتجع** ولا على **المشوار كله**؟

## ٦. الطباعة — مفيش API

دوّرنا في 209 query و 206 mutation: **مفيش أي عملية بترجّع بوليصة**.
البوليصة **بتترسم في المتصفح** بقوالب React جوه البورتال:

```
waybill/shipment/default/:id
waybill/:type/A4/:template/:id
waybill/:type/sticky-print/:template/:id
```

المقاسات: `5X2` · `5X4` · `7X9` · `10X10` · `10X15` — وA4 بـ `1c/2c/3c/2d/3d`.

**ليه دي أهم مشكلة فاضلة:** تالا مفيهاش Smart Label، فكل طرد تالا **لازم** يتطبعله بوليصة
— مفيش طريق تاني. ومعنى كده إن مسار "التاجر يمسح الملصق" بتاع بوسطة لازم يتقفل لما
السويتش يكون على تالا.

**المشكلة العملية:** ده رابط في موقعهم محتاج جلسة مسجّلة دخول. التجار عندنا مالهمش
حسابات على تالا، فمش هيقدروا يطبعوا. الحلول: (أ) نطلب API للطباعة، (ب) نرسم الملصق
بنفسنا من بيانات الشحنة + باركود الـ `code`، (ج) الأدمن بس يطبع من البورتال.

## ٧. الـ Webhook — عن طريق `Integration`

تالا عندها كيان اسمه `Integration` معمول للحالة بتاعتنا بالظبط:

```
integrationUrl   ← رابط الـ webhook بتاعنا
token            ← السيكرت
useSenderData    ← يستخدم بيانات الراسل اللي بنبعتها
useShipmentCode  ← يسمحلنا نحدد كود الشحنة (مش هنستخدمه)
useRemoteAgent
zones / services / cancellationReasons  ← جداول ربط بين أرقامنا وأرقامهم
```

`typeCode` المتاحة: `ACCURATE` · **`BOSTA`** · `SINDBAD` · `OTO` · `MEGA` · `VISION` · `OTHER`

**حسابنا `integration: null`** — مفيش حاجة متظبطة. ده اللي تالا لازم تعمله لينا،
و`saveIntegration` محظورة علينا فمش هنقدر نعملها بنفسنا.

**شكل الـ callback** (من الدوكيومنتيشن، لسه متأكدناش منه عملياً):
```json
{ "shipmentId", "typeCode", "shipmentStatusCode", "returnTypeCode",
  "deliveryTypeCode", "deliveredAmount", "collectedFees",
  "deliveryDate", "cancellationReasonId", "notes" }
```
⚠️ **مفيش `timestamp`** — لو وصلت تحديثات بترتيب غلط مش هنعرف أنهي أحدث.

**بديل:** البورتال بيستخدم `graphql/subscriptions/auth` — يعني عندهم WebSocket
subscriptions. يمكن تنفع كبديل أو إضافة للـ webhook.
